# 串口协议 v2.0

物理层：115200、8N1。默认内部时钟 5 MHz。推荐上位机每次发送一条请求，收到对应回复后再发送下一条；队列用于吸收短时突发，不提供持续超速流控。

## 带 CRC 的推荐格式

请求共 8 字节：`A5 5A SEQ CMD ADDR_H ADDR_L DATA CRC`。

回复共 9 字节：`5A A5 SEQ STATUS CMD ADDR_H ADDR_L DATA CRC`。

CRC-8/SMBUS：多项式 0x07、初值 0、不反射、最终异或 0，覆盖当前帧 CRC 之前的全部字节。标准检查值 `CRC("123456789")=0xF4`。SEQ 原样返回，便于识别回复。DATA 在读/状态请求中为占位字节。

| CMD | 功能 | 成功回复的 DATA |
| --- | --- | --- |
| 01 | 写一个寄存器 | 写入值；表示 SPI 传输已完成，不代表读回一致 |
| 02 | 读一个寄存器 | 读取值 |
| 03 | 查询桥接状态 | 按状态地址返回信息 |
| 04 | 写入后回读并逐位比较 | 实际读取值；不一致时 STATUS=05 |

SPI 地址必须在 0x0000～0x1FFF；高位越界会报错。04 适用于普通稳定可读写寄存器，不适用于自清零、只写、只读或含动态状态的寄存器。

| STATUS | 含义 |
| --- | --- |
| 00 | 成功 |
| 01 | 请求 CRC 错误，未执行 SPI |
| 02 | 未知命令 |
| 03 | 等待事务受理或回复超时 |
| 04 | 地址无效 |
| 05 | 写后回读值不一致，DATA 返回实际值 |

CRC 错误的完整帧也会排队返回错误；其 SEQ/CMD/地址仅来自收到的未校验字节。主机应检查回复 CRC 和事务标识。部分帧字节间隔超过 20 ms 则丢弃并复位解析器，设置接收异常标志；部分帧没有完整事务标识，因此不会回复。命令等待受理和等待 SPI 回复分别限制为 100 ms。

队列深度为 4 条，另外可有 1 条正在执行或回复。满队列的新请求被丢弃，置位溢出标志；不会覆盖已入队事务。丢弃请求没有回复，主机应超时报告，禁止默认自动重试写操作。旧格式缺少帧头，混合噪声条件下无法提供与新格式相同的同步保证。CRC 用于传输检错，不用于身份认证。

## 状态查询（CMD=03）

| 地址 | 含义 |
| --- | --- |
| 0000 | 状态标志，见下表 |
| 0001 | 首次自动校验失败地址 [12:8]，高 3 位为 0 |
| 0002 | 首次自动校验失败地址 [7:0] |
| 0003 | 首次失败的期望值 |
| 0004 | 首次失败的实际回读值 |
| 0005 | 协议版本 0x20 |

| 状态位 | 含义 |
| --- | --- |
| 0 | FPGA 内部时钟生成 IP locked |
| 1 | 242 条初始化写操作已完成 |
| 2 | 5 个关键寄存器校验已结束 |
| 3 | 自动校验失败，复位前保持 |
| 4 | HMC7044 GPIO 两级同步后的电平 |
| 5 | SPI 控制器当前忙 |
| 6 | 命令队列曾溢出，复位前保持 |
| 7 | 曾发生 UART 停止位错误或半帧接收超时，复位前保持 |

00A～00E 的校验仅比较掩码 0x1F 内的稳定配置位，期望值依次为 06、07、06、06、07；保留位不参与比较。失败后仍释放总线，允许主机查询错误和继续调试。自动校验是上电一次性快照，后续在线写入不会自动刷新该结果。初始化写完、回读一致和 PLL 锁定是三个独立状态。

原始寄存器表保持不变，其中 0x0050=0x37 对应 GPO1 的 PLL1 与 PLL2 联合锁定指示，不应称为单独 PLL2 锁定。状态位 4 报告板上 hmc7044_gpio1 引脚同步电平；实际物理连接需在上板时确认。0x0051=0x33 配置的是另一个输出功能。在线修改 GPO 功能后，该位应按新的引脚功能解释。

## 兼容四字节格式

请求：`CMD ADDR_H ADDR_L DATA`；回复仍为相同命令和地址加结果数据。01/02 与原工程成功格式一致，03/04 为扩展。失败时最后一字节为 EE，因此旧格式无法区分“错误”与合法的 0xEE 读数，应优先使用新格式。读命令必须发送第 4 个占位字节。

## 使用上位机工具

安装依赖：`python -m pip install -r host/requirements.txt`。

```text
python host/clock_bridge.py --port COM5 status
python host/clock_bridge.py --port COM5 read 0x78
python host/clock_bridge.py --port COM5 write 0x08 0x5A
python host/clock_bridge.py --port COM5 verify 0x08 0xA5
python host/clock_bridge.py --port COM5 --legacy read 0x08
```

0x0008 是数据手册定义的不影响芯片运行的读写测试暂存器，适合首轮连通性演示。工具默认采用新协议，不自动重试写命令。

图形界面使用 Qt 6 / PySide6，提供串口连接、寄存器读写和校验、状态查询、CSV 批量操作及通信日志。安装 `host/requirements-gui.txt` 后运行 `python host/clock_bridge_gui.py`，或使用 `host/dist/ClockBridgeStudio/ClockBridgeStudio.exe` 免安装版。使用方法见 [Qt 上位机说明](../host/README_GUI.md)。GUI 仅使用 v2 CRC 协议；离线演示使用本地软件模型，不代表上板结果。
